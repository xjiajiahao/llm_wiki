# DeepSeek V3 vs V4

## 核心转向

这两份报告最显著的差异，不是单个模块，而是优化目标的变化：

- `V3` 主要回答“超大规模 `MoE` 训练和推理能否足够经济、足够稳定”。
- `V4` 主要回答“在百万 token 级上下文下，长程推理和 agent 工作负载能否变得可行”。

## 延续点

- 两代都保留了 `MoE` 骨架。
- 两代都把系统工程视为研究贡献，而不是实现细节。
- 两代都保留了 `multi-token prediction` 这条训练目标线索。
- 两代都不是“只有预训练”，而是包含明显的后训练流程。

## 主要变化

- `V3` 强调 `MLA`、`DeepSeekMoE`、无辅助损失负载均衡、`FP8` 与并行基础设施。
- `V4` 在保留 `MoE/MTP` 基底的同时，把注意力主叙事改成 `CSA + HCA`，并加入 `mHC`、`Muon` 与 `FP4`。
- `V3` 报告的上下文扩展重点是 `128K`；`V4` 的 headline capability 是原生 `1M token`。
- `V3` 更强调总训练成本（`2.788M H800 GPU hours`）；`V4` 更强调相对 `DeepSeek-V3.2` 的单 token FLOPs 与 KV cache 压缩比例。

## 工作性理解

如果把两篇报告放在一起看，可以把它们理解成同一条研发路线的相邻阶段：

- 阶段一：证明前沿级开源 `MoE` 可以高效、稳定地训练出来。
- 阶段二：把节省下来的效率预算，转投到长时程推理、超长上下文和 agent 执行上。

## 后续问题

- `V3` 的哪些系统设计原样延续到 `V4`，哪些被替换了？
- `V4` 的收益里，多少来自注意力压缩，多少来自其他基础设施升级？
- 是否应该单独为 `DeepSeek-V3.2` 和 `DeepSeek-R1` 建页，以便把谱系关系写清楚？
